앞서 제공해 드린 기본적인 운영 가이드 외에, 시스템의 복잡도가 높아질 미래를 대비하여 **개발자용 기술 문서(Technical Documentation)**와 **데이터 흐름도**를 추가로 작성해 드립니다. 이 내용은 코드의 내부 로직을 이해하고 기능을 확장하는 데 핵심적인 지도가 될 것입니다.

### 5. 시스템 아키텍처 및 데이터 흐름도 (Architecture & Data Flow)

이 문서는 전체 시스템의 구성 요소 간 상호작용을 설명합니다.

* **시스템 구조**: `Next.js App Router` 기반 프론트엔드 + `API Routes` 백엔드
* **데이터 흐름**:
1. **초기화**: 사용자가 페이지 접속 시 `/api/init` 호출 → 구글 시트('유저 정보', '마트') 데이터 로드
2. **데이터 입력**: 사용자가 3단계 폼을 통해 요청 사항 입력 및 유효성 검사 수행
3. **제출 처리**: `/api/submit` 호출 (JSON 데이터 전송)
4. **백엔드 로직**:
* 데이터 카테고리 분석 및 품목별 행(Row) 분리
* 구글 시트('내역')에 데이터 기록 및 '로그' 시트에 결과 저장
* Slack Webhook을 통한 항목별 개별 알림 발송





### 6. API 상세 명세서 (API Specification)

프론트엔드와 백엔드 간의 통신 규약입니다.

#### [GET] `/api/init`

* **설명**: 폼 초기화에 필요한 기본 데이터를 구글 시트에서 가져옵니다.
* **응답 데이터**:
* `users`: 요청자 이름 목록 (String[])
* `marts`: 마트 객체 배열 (Object[]) - `name`, `orderable`, `manager`, `id` 등 포함



#### [POST] `/api/submit`

* **설명**: 사용자 요청을 처리하고 시트 기록 및 슬랙 알림을 수행합니다.
* **주요 로직**:
* **행 분리(Row Splitting)**: 한 번의 요청에 여러 품목이 있을 경우 품목별로 새로운 ID를 생성하여 개별 행으로 저장합니다.
* **인덱스 고정**: 데이터 유실 방지를 위해 30칸의 고정 배열(`Array(30).fill('')`)을 생성한 후 특정 인덱스에 값을 할당합니다.



### 7. 프론트엔드 컴포넌트 구조도

UI 구성 요소의 계층 구조와 역할입니다.

* **`Home (page.js)`**: 전체 상태(State) 관리 및 단계별 네비게이션 로직 담당
* **`Step1_BasicInfo`**: 요청자 및 마트 검색/선택 섹션
* **`Step2_Items`**: 품목별 탭 메뉴 및 상세 입력 (X배너, 현수막 등)
* **`Step3_Confirm`**: 입력 내역 요약 확인 및 최종 마감일 선택
* **`DesignModal`**: 이미지 기반 디자인 선택 도구 (모바일 최적화)
* **`CustomAlert`**: 브라우저 기본 알림을 대체하는 공통 모달 시스템

### 8. 개발 가이드라인 (Developer Guidelines)

신규 개발자가 프로젝트에 참여할 때 준수해야 할 규칙입니다.

* **상대 경로 사용**: Vercel 빌드 에러 방지를 위해 `lib` 또는 `components` 참조 시 반드시 상대 경로(예: `../../../lib/google`)를 사용합니다.
* **날짜 처리**: 모든 날짜와 시간 기록은 `Asia/Seoul` 타임존을 명시적으로 지정하여 서버(Vercel) 환경과 관계없이 일관성을 유지합니다.
* **스타일 관리**: 공통 스타일은 `page.module.css`에, 컴포넌트 특화 스타일은 해당 모듈 CSS에 분리하여 작성합니다.
